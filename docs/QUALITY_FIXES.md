# Quality fixes for the plan stage (2026-11-25)

Source: the quality audit of the plan stage (`docs/audit/2026-11-25/REPORT.md`, 40 prompts). This document says what changed, how to switch it off, how to measure it and what it does not solve. Measured result: `docs/audit/2026-11-25-after/COMPARISON.md`.

## The switch

`QUALITY_FIXES` (environment variable of the plan Lambda; default **on**). `QUALITY_FIXES=0` (also `off`, `false`, `no`) restores the previous behaviour exactly: old prompts, old length range (90 to 110 percent), no retries or escalation, no grounding check, no extra section retry, the old default User-Agent (`explainer-engine/2.0`) and the old screen/narration check. Rollback is one setting, no deploy of code. (To set it from the stack, add `QUALITY_FIXES` to the environment of the plan handler; today it is read from the process environment, so a Lambda environment variable is enough.)

## What changed (by audit finding)

| # | Finding | Change | Where |
|---|---|---|---|
| 1 | 16 of 40 videos had under 1,500 characters of notes, 14 none; Wikimedia 429s were swallowed | Every Wikipedia fetch is logged (`RESEARCH_FETCH_FAILED url=... status=...`, never prompt text), retried up to 3 times with exponential backoff, honouring `Retry-After` (capped at 4 s, about 10 s in total), at most 2 requests in flight and 0.3 s between request starts for the whole process; one bad page no longer ends the whole search; the failures are returned as `research.fetch_errors` / `fetch_errors_n` by `director.direct`. **Thin-notes fallback:** when the encyclopedia path ends under 1,500 characters or with no source, and a web provider exists, the web research agent runs (its normal budget) before writing; recorded as `research.escalated` (`from_chars`, searches, sources, cost); not done for staged videos (their sections research on the web anyway) or photo videos. When nothing is found the writer is told explicitly: "No sources were found... Stay general". | `netsafe.py`, `research.py`, `director.py`, `plan.py` (`no_notes_text`), `staged.py` |
| 1b | User-Agent | `netsafe.user_agent()`: `HTTP_USER_AGENT` when set, else `videomk/1.0`. Used by every `fetch_bytes`/`fetch_json` call (Wikipedia, Commons, Pexels, Pixabay, images, page reads) and the Tavily call. **The owner must supply the real value** (context key `httpUserAgent`, see `backend_stack.py`), a descriptive agent with a contact, for example `videomk/1.0 (https://<site>; <contact email>)`; no address was invented. | 2 | Invented or unsupported specifics (79 accuracy defects, 25 major) | Two compact rules in the director prompt (also used by the staged section writers, which build on it), about 400 characters: every number, date, name, quantity, feature, study or quote must come from the notes or the person's own request/brief, else speak generally or leave it out; for product, marketing and health use only what the person gave or the notes; never say "the notes", "our notes", "the sources", "the research" (nor the Spanish forms) aloud. | `plan.py` (`GROUNDING_RULE`) |
| 3 | No claim-level check after writing | `quality.ground_check` after the script (single-pass and staged): numbers (not ordinals or the small integers 0 to 10 without a unit), years, capitalised names, quotes and "the notes" leaks that appear nowhere in the notes, the request or the brief are sent in ONE small-model call, which says per candidate `notes` / `common` (well-known, kept) / `unsupported` (conservative bias to keep correct well-known facts) and rewrites only the sentences with unsupported specifics. No call at all when nothing is flagged. Specifics that the screen shows too are left alone (cutting them from the narration alone would break the sync). Product/marketing videos also have every beat reviewed for invented features, policies, prices (the rules cannot see those). Fiction requests skip names. Counts: log `GROUNDING flagged=N repaired=M`, `research.grounding`, and a plan warning `grounding: ...`. | `quality.py`, `director.py` |
| 4 | Short videos run 1.18 to 1.23 times the target | The writer is asked for 92 to 105 percent of the words (was 90 to 110) in the single-pass and the section prompts, and `plan.long_problem` sends a script over 112 percent back ONCE to be trimmed (sections: over 115 percent), keeping the first script if the trimmed one is shorter than 92 percent, still not shorter than the first, or fails; a remaining overshoot is a `length:` warning. `SPOKEN_WORDS_PER_S`, `BEAT_OVERHEAD_S`, `expected_words` and `expected_beats` were **not** changed: the audit's speech estimate uses the same constants, so it cannot show that they are wrong; the overshoot was the writer exceeding the requested words (1.23 times the expected words at 1 minute). To recalibrate the constants, measure TTS durations of rendered videos. | `plan.py`, `staged.py` |
| 5 | Screen and narration mismatch; scenes replaced as invalid | (a) Prompt rule: every item of a bullets, steps, timeline, versus or diagram scene is named in that beat's narration, in the order shown, items a few words long. (b) The check (`sync.coverage_problems`) no longer asks for more than the screen needs: a timeline is judged on its event labels (not on dates read in the same form) and a gallery of stock photos on one shared word per photo after the first, as the timeline anchoring does; a list whose items are never said is still flagged. (c) A scene replaced as invalid (`versus needs 2+ rows`, `bar_race`) gets ONE small-model call to correct it (up to 4 scenes, same sanitiser) before the title card stays. | `plan.py`, `sync.py`, `quality.py` (`repair_scenes`), `director.py` |
| 6 | A staged section failed with "no JSON object in model output" | One extra attempt with a strict "only one JSON object, no commentary" reminder when an answer has no JSON; the first 300 characters of an unparseable answer are logged (`SECTION_NO_JSON`; model output only, never the prompt). | `staged.py` |

## Cost and latency

The grounding check is one Haiku call per video with candidates (a fraction of a cent, none when nothing is flagged); the thin-notes escalation adds the web agent (about 0.01 to 0.03 USD) to videos that would otherwise run on almost no notes; the trim repair adds one script call to the minority of short videos that overshoot by more than 12 percent. See the comparison for the measured totals.

## Known limits

* The check sees digits only: a spelled-out number ("seventy percent"), a sentence-initial name and a vague claim are invisible to the rules (only the product/marketing review looks at claims). A fact the model "knows" wrongly is kept as `common`; the judge and a human are still the check for that.
* The grounding repair rewrites narration only. A number that is also on screen is left (the screen and the voice must agree), so it stays as written.
* Escalation needs a web provider (Tavily key). Without one a thin result still reaches the writer, now with the "stay general" note.
* A persistent Wikimedia block (an address throttled for a long time, or a User-Agent without contact) is only mitigated by retries, spacing and escalation, not cured: set `httpUserAgent` with a real contact.
* The length trim relies on the writer; a script that stays over 112 percent after the one retry is kept with a warning. The words-per-second constant was not re-measured.
* The looser coverage check lowers the mismatch count by definition; `audit_compare.py` also reports the strict rule on both sets.
* `QUALITY_FIXES` is read per call; the User-Agent constant `netsafe.USER_AGENT` (used by `clips.py` to decide whether Commons candidates are allowed) is fixed at import and equals the default `videomk/1.0` or the configured value.
